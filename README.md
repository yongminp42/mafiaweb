# MAFIAGAME

> 현재 버전: **0.5.2-alpha**

MAFIAGAME은 웹 브라우저에서 여러 명이 실시간으로 플레이하는 소셜 추리 게임입니다. Spring Boot 서버가 게임 상태와 페이즈 타이머를 관리하고, Thymeleaf 화면과 STOMP WebSocket이 참가자·채팅·투표·역할 정보를 실시간으로 동기화합니다.

## 어떤 게임인가요?

마피아 게임은 참가자에게 비밀 역할을 나누어 주고, 낮에는 토론과 투표로 마피아를 찾아내며, 밤에는 각 역할의 행동으로 다음 날의 결과를 만드는 게임입니다. 다른 참가자의 역할을 직접 확인할 수 없기 때문에 공개 대화, 투표 결과, 밤의 사망·보호 결과를 조합해 추리해야 합니다.

MAFIAGAME의 MVP는 한 방에 **4~8명**이 참여하는 방식입니다. 방장은 참가자 전원이 준비된 상태에서 게임을 시작할 수 있고, 게임이 끝나면 같은 방이 다시 `WAITING` 상태로 초기화되어 재플레이할 수 있습니다. 현재 MVP에는 관전자 모드를 포함하지 않습니다.

### 역할

| 역할 | 진영 | 핵심 행동 |
| --- | --- | --- |
| 마피아 (`MAFIA`) | 마피아 | 밤에 제거할 대상을 선택하고, 마피아 채널에서 동료와 협력합니다. |
| 스파이 (`SPY`) | 마피아 | 밤에 상대의 직업을 조사하며 마피아를 찾으면 마피아 채널에 접선합니다. 살해 능력은 없습니다. |
| 경찰 (`POLICE`) | 시민 | 밤에 한 명을 조사하여 마피아팀인지 확인합니다. 결과는 경찰 본인에게만 전달됩니다. |
| 의사 (`DOCTOR`) | 시민 | 밤에 한 명을 보호하여 마피아의 제거를 막습니다. 자기 자신도 보호할 수 있습니다. |
| 군인 (`SOLDIER`) | 시민 | 마피아의 밤 공격을 한 번 막고, 무적이 발동하면 직업을 전체에 공개합니다. |
| 영매사 (`MEDIUM`) | 시민 | 생존 중에도 사망자 채널을 사용하고 밤에 사망자의 직업을 조사합니다. |
| 시민 (`CITIZEN`) | 시민 | 특수 밤 행동 없이 낮 토론과 투표로 마피아를 찾아냅니다. |

역할은 개인 WebSocket 큐로만 전달되며 공개 게임 상태에는 노출되지 않습니다. 사망한 참가자는 이후 투표와 역할 행동에 참여할 수 없습니다.

### 게임 진행

```text
WAITING
  → ROLE_ASSIGNMENT (역할 확인, 15초 또는 전원 확인)
  → NIGHT (첫 밤 행동, 35초)
  → DAY_DISCUSSION (낮 토론, 60초)
  → NOMINATION_VOTE (지목 투표, 20초)
  → FINAL_DEFENSE (단독 지목 시 최종 변론, 20초)
  → EXECUTION_VOTE (처형 찬반 투표, 20초)
  → NIGHT (마피아팀·의사·경찰·스파이·영매사 행동, 35초)
  → 다음 날 또는 FINISHED
```

- 지목 투표는 생존자만 참여할 수 있고 자기 자신을 지목할 수 없습니다.
- 지목 동률 또는 무투표이면 처형 투표 없이 밤으로 넘어갑니다.
- 최종 변론에서는 지목된 참가자만 공개 채팅을 사용할 수 있습니다.
- 처형 후보자는 처형 투표를 할 수 없으며, 찬성이 반대보다 많을 때 처형됩니다.
- 6명·8명 구성에는 스파이가 포함되며, 스파이는 마피아를 조사해 마피아팀을 확인한 경우에만 마피아 채널에 접선할 수 있습니다. 5명 구성은 마피아 1명·경찰 1명·의사 1명·시민 2명, 7명 구성은 마피아 2명·경찰 1명·의사 1명·군인 1명·영매사 1명·시민 1명입니다.
- 6명 이상에서는 군인이 마피아의 첫 공격을 한 번 막고, 생존하면 전체 참가자에게 직업을 공개합니다.
- 7~8명 구성의 영매사는 생존 중에도 사망자 채널을 사용할 수 있고, 밤에 사망자의 직업을 조사할 수 있습니다.
- 시민 진영은 마피아팀(마피아·스파이) 생존자가 모두 없어지면 승리합니다.
- 마피아 진영은 생존 마피아 수와 접선한 생존 스파이 수가 생존 시민 진영 수 이상이면 승리합니다.
- 게임 종료 시 승리 진영, 본인 역할, 생존 여부와 전체 역할 결과를 확인할 수 있습니다.
- 완료된 게임의 총 게임 수·승리 수·패배 수를 계정 통계에 누적하고 프로필에 표시합니다.

## 주요 기능

- 회원가입·로그인·로그아웃 및 Spring Security 기반 접근 제어
- 4~8명 게임방 생성, 입장, 검색, 정원 검증
- 방장·참가자·Ready 상태의 실시간 동기화
- 공개 채팅, 마피아 채팅, 사망자 채팅의 서버 측 분리
- 서버 기준 페이즈 전환과 `phaseEndsAt` 기반 타이머 동기화
- 역할별 밤 행동, 승패 즉시 판정, 결과 표시 및 같은 방 재플레이
- 역할 확인 후 첫 밤부터 시작하고 첫 밤 결과 뒤 낮 토론으로 진행
- 완료 게임별 계정 승·패 통계의 중복 방지 집계
- 마지막 연결 종료 뒤 게임 중 30초 재접속 유예와 방장 변경 유예 분리
- 4~8명 인원수별 역할 구성과 스파이·군인·영매사 특수 규칙
- 방장 전용 게임방 설정, 실시간 정원 동기화, 게임방 비밀번호 설정·변경·해제
- 새로고침·재접속·일시적인 연결 종료 후 상태 복구
- 각 페이즈의 결과와 마피아 게임 안내를 공개 `SYSTEM` 메시지로 표시
- 역할 확인, 낮 토론, 투표, 밤 행동, 게임 종료 안내를 포함한 페이즈별 시스템 메시지
- 마피아·사망자·영매사·스파이의 상태에 따른 채널 접근 및 메시지 수신자 분리
- 게임 종료 후 전체 채널만 허용하고, 경찰 조사 결과에는 대상 진영만 표시
- 로비 진입 시 패치노트 팝업 표시, 오늘 하루 숨김, 전체 버전 패치노트 상세보기

## 실행 방법

### 사전 요구사항

- JDK 17
- Node.js 20.19 이상(20계열), 22.12 이상(22계열) 또는 24 이상 및 npm (`package-lock.json`의 `jsdom` 요구 버전 기준)
- MariaDB — 기본 URL은 `jdbc:mariadb://localhost:23306/mafiaweb`

DB 계정은 환경 변수로 지정합니다.

```powershell
$env:DB_USERNAME = "mafia_app"
$env:DB_PASSWORD = "replace-with-a-strong-local-password"
```

### Windows

```powershell
npm ci
.\gradlew.bat test
.\gradlew.bat bootRun
```

### macOS / Linux

```bash
npm ci
./gradlew test
./gradlew bootRun
```

실행 후 [http://localhost:8080](http://localhost:8080)에 접속합니다.

현재 `/ws`는 `https://mafiaweb01.duckdns.org` Origin만 허용합니다. 로컬 HTTP 화면에서는 WebSocket 연결이 거부될 수 있으므로, 실시간 게임 확인 전 접속 Origin 설정을 확인해야 합니다.

### 테스트 명령

```powershell
# Java + JavaScript 테스트
.\gradlew.bat test

# JavaScript 테스트만
npm run test:js

# Playwright 핵심 E2E
$env:PLAYER_COUNTS = "4,5,6,8"
npm run test:e2e -- --workers=1
```

## 패치노트

### 0.5.2-alpha — 회원가입 동의 안내·게임 규칙 정리·게임방 화면 개선

0.5.2-alpha에서는 회원가입에 필요한 동의 절차를 실제 화면과 서버 검증으로 연결하고, 게임방 도움말을 현재 규칙에 맞게 정리했습니다. 대기방과 게임 화면의 세로 배치를 조정해 플레이 영역과 액션 행이 더 안정적으로 보이도록 했으며, QA 실행 재현성과 테스트 사전 검증도 보강했습니다.

#### 회원가입 동의 안내

- 회원가입 화면에서 이용약관과 개인정보 처리방침을 각각 모달로 확인할 수 있습니다.
- 동의 체크박스를 서버가 필수 입력으로 확인하며, 동의하지 않으면 가입을 처리하지 않고 안내 문구를 표시합니다. 입력 오류로 돌아온 화면에서도 동의 상태를 유지합니다.
- 개인정보 안내에는 실제로 처리하는 가입·프로필·게임·실시간 이용 정보와 비밀번호 처리 방식을 설명하고, 동의 사실을 별도 데이터베이스 항목으로 저장하지 않는 현재 동작을 명시했습니다.

#### 게임 규칙과 도움말 정리

- 게임방 도움말의 시민팀·마피아팀 승리 조건을 서버 판정과 맞췄습니다. 접선하지 않은 스파이는 마피아팀 동수 판정에서 제외됩니다.
- 역할 확인 뒤 첫 밤을 진행하는 실제 순서를 도움말에 표시하고, 정원별 역할 구성 표를 기준으로 참가 인원에 맞는 배정 안내를 제공합니다.
- 문구와 역할 안내를 현재 4~8명 게임 규칙에 맞춰 정리해 화면 설명과 실제 진행 사이의 혼동을 줄였습니다.

#### 게임방 화면 배치

- 게임방 제목·인원 정보 상자 아래 간격을 줄이고 콘텐츠 하단 여백을 늘려 게임 플레이 영역이 화면 아래로 치우치지 않고 중앙에 놓이도록 조정했습니다.
- 준비·시작 액션 행을 전체 왼쪽 열 안에서 정렬하고, 참가자 카드가 길어질 때도 액션 행을 스크롤해 사용할 수 있게 했습니다.
- 대기·진행 게임 패널의 높이와 참가자·채팅 열 정렬 기준을 유지하면서 데스크톱과 모바일 배치를 함께 보정했습니다.

#### QA·안정성

- Smoke·Regression·Full 프로필이 같은 중앙 정렬 UI 기준을 사용하도록 QA 스크립트와 E2E 프로필을 정리했습니다.
- 실행 ID를 안전한 문자와 22자 이내로 제한해 Full 확장 시나리오에서도 가입 닉네임이 30자 제한을 넘지 않게 했습니다. 잘못된 ID는 DB 확인과 서버 시작 전에 거부합니다.
- QA 서버의 Java 임시 디렉터리를 실행별 절대 경로로 고정하고, 공통 실행 ID·닉네임 검증과 프로필 경계 테스트를 추가했습니다.
- `RoomGameRules`의 역할 수 집계에서 null 안정성 경고가 발생하지 않도록 명시적 정수 연산으로 정리했습니다.
- Gradle 프로젝트 버전을 0.5.1-alpha에서 0.5.2-alpha로 변경했습니다.

### 0.5.1-alpha — 닉네임 중복 방지·정원별 역할 안내·마피아 동료 표시

0.5.1-alpha에서는 회원가입 때 닉네임 중복을 막고, 게임방 도움말에 방 최대 인원 기준의 역할 구성을 표시합니다. 게임 시작 시 마피아 역할을 받은 플레이어에게 다른 마피아 역할 보유자의 닉네임도 개인적으로 알려줍니다.

#### 회원가입 닉네임 중복 방지

- 닉네임 앞뒤 공백을 정리한 뒤 이미 사용 중인지 확인하고, 중복이면 회원가입을 거부하며 안내 문구를 보여줍니다.
- 동시 회원가입으로 사전 확인 사이에 중복 요청이 들어오는 경우도 막도록 `user_name`에 데이터베이스 유일 제약을 추가했습니다. 이메일과 닉네임 중 실제로 충돌한 항목에 맞는 오류를 반환합니다.

#### 방 정원 기준 역할 구성 안내

- 게임방 도움말에 현재 참가자 수가 아니라 방의 최대 인원(4~8명)에 맞는 역할 구성을 표시합니다. 설정에서 정원을 바꾸면 도움말도 해당 정원 구성으로 갱신됩니다.
- 역할 구성 수는 실제 게임에 사용하는 공통 규칙에서 만들어 화면과 서버의 역할표가 달라지지 않게 했습니다.

| 방 최대 인원 | 역할 구성 |
| ---: | --- |

| 5명 | 마피아 1, 경찰 1, 의사 1, 시민 2 |

#### 로비 목록과 실시간 갱신 경로

- 방 목록의 findAll·findById에서 참가자 테이블을 조인해 매 방마다 인원수를 세던 작업을 제거했습니다. DB에서는 방 메타데이터를 읽고, 화면에 필요한 현재 인원·접속 수는 실시간 메모리 상태로 합칩니다.
- 준비 상태 스냅샷은 메모리에 보관한 방 설정과 상태를 사용합니다. 입장 검증의 DB 읽기와 빈 방 삭제 작업은 공용 쓰기 잠금 밖에서 수행하되, 잠금을 얻은 뒤 삭제 세대와 진행 상태를 재확인해 삭제된 방에 오래된 조회 결과로 재입장하지 않도록 했습니다.
- 이벤트가 목록에 없는 새 방을 가리키면 전체 로비 화면을 다시 받지 않고 /rooms/{roomId}/card에서 Thymeleaf 방 카드 하나만 받아 기존 목록에 삽입합니다. 검색·상태 필터·방 번호를 다시 계산하고, 응답 도중 방이 삭제되거나 인원이 0명이 된 경우 오래된 카드를 넣지 않습니다.
- 참가 인원 또는 온라인 인원이 직전 전송 값과 달라졌을 때만 로비 인원 메시지를 보냅니다. 초기 전체 스냅샷은 계속 보내 새 구독자 화면을 동기화합니다.
- 빈 방 정리·방장 이전 등 유지보수 예약 작업을 처리하는 작업자는 2개로 늘리고, 로비 인원 브로드캐스트는 전용 작업자 1개로 분리했습니다. 방 생성과 설정 변경의 최대 인원·비밀번호 검증은 공통 함수로 모으되 기존 규칙과 오류 문구는 유지했습니다.

- 메인 화면에 버전별 패치노트 상세 보기를 추가하고, 내용이 달라지면 오늘 하루 숨김 설정을 다시 적용하도록 했습니다.
- Smoke·Regression·Full의 인원수, 재플레이, UI 및 증거 보관 기준을 실행 스크립트와 QA 문서에 맞췄습니다.
- Gradle 프로젝트 버전을 0.2.0-alpha에서 0.3.0-alpha로 변경했습니다.

### 0.2.0-alpha — 역할 확장·서버 채널 권한·페이즈 안내

#### 당시 인원수별 역할 구성

- 4명: 마피아 1명, 경찰 1명, 의사 1명, 시민 1명
- 5명: 마피아 1명, 스파이 1명, 경찰 1명, 의사 1명, 시민 1명
- 6명: 마피아 1명, 스파이 1명, 경찰 1명, 의사 1명, 군인 1명, 시민 1명
- 7명: 마피아 2명, 스파이 1명, 경찰 1명, 의사 1명, 군인 1명, 시민 1명
- 8명: 마피아 2명, 스파이 1명, 경찰 1명, 의사 1명, 군인 1명, 영매사 1명, 시민 1명

5명과 7명 구성이 0.4.0-alpha에서 조정됐습니다. 현재 역할표는 최신 버전 기준의 0.4.0-alpha 항목을 참고하세요.

#### 역할 능력과 진행 규칙

- 스파이는 마피아팀으로 추가했습니다. 밤에 직업을 조사하고 마피아를 찾으면 접선해 마피아 채널을 이용할 수 있지만, 직접 살해 행동은 하지 않습니다.
- 군인은 마피아의 밤 공격을 한 번 막습니다. 영매사는 생존 중 사망자 채널을 쓸 수 있고 밤에 사망자의 직업을 조사할 수 있습니다.
- 당시 페이즈 시간은 역할 확인 10초, 낮 토론 60초, 지목·최종 변론·처형 투표 각 15초, 밤 행동 30초였습니다.
- 마피아·사망자 채널, 역할 행동과 투표 가능 여부를 서버에서 확인해 채널 권한 우회를 막았습니다.
- 페이즈 안내 시스템 메시지와 게임 종료 후 재플레이, 새로고침·재접속 상태 복원을 보강했습니다.
- WebSocket의 null 안정성, 채팅 UI 및 Java·JavaScript·Playwright QA 범위를 함께 정리했습니다.
- Gradle 프로젝트 버전을 0.1.1-alpha에서 0.2.0-alpha로 변경했습니다.

### 0.1.1-alpha — 페이즈 안내 메시지·채팅 UI·기초 QA

- 게임 시작과 실제 페이즈 전환 때 공개 시스템 메시지로 규칙, 다음 행동, 밤·처형 결과를 안내합니다. 재접속이나 상태 동기화만으로 같은 안내를 중복 발행하지 않도록 했습니다.

- WebSocket 인가·null 안정성과 Java·JavaScript·Playwright 테스트 및 재사용 QA 실행 문서를 보강했습니다.
- Gradle 프로젝트 버전을 0.1.0-alpha에서 0.1.1-alpha로 변경했습니다.
