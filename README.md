# 웹 실시간 마피아 게임 MVP 개발 체크리스트

> 기준: Java 21, Spring Boot 4.0.8, Thymeleaf, Spring Security, MyBatis, MariaDB, WebSocket(STOMP)
>
> 목표: 4~8명이 방에 입장해 준비, 직업 배정, 낮 토론, 투표, 밤 행동, 승패 판정까지 한 판을 완주한다.

## 0. 개발 전 범위 확정

- [ ] MVP 지원 인원을 4~8명으로 확정한다.
- [ ] 방 최대 인원 옵션을 6명/8명으로 제한할지 결정한다.
- [ ] 비회원 플레이 허용 여부를 결정한다.
- [ ] MVP에서는 한 서버 인스턴스만 운영한다는 조건을 명시한다.
- [ ] 재접속 허용 시간과 재접속 실패 처리 방식을 정한다.
- [ ] 동률 투표 처리 규칙을 정한다.
- [ ] 방장이 나가거나 연결이 끊겼을 때 방장 위임 규칙을 정한다.
- [ ] 게임 도중 이탈자를 사망 처리할지, 재접속 대기 처리할지 정한다.
- [ ] MVP 제외 기능을 기록한다. 예: 친구, 랭킹, 음성 채팅, 신고, 매칭, 아이템.

## 1. 프로젝트 기반 정리

- [ ] Gradle Wrapper 8.14.5와 Java 21 환경에서 빌드되는지 확인한다.
- [ ] Spring Boot 버전을 현재 프로젝트의 4.0.8로 통일한다.
- [x] 데이터 접근 기술을 MyBatis로 통일한다.
- [ ] 사용하지 않는 `spring-boot-starter-data-jdbc` 등 중복 의존성을 제거한다.
- [ ] WebSocket 의존성 버전을 Spring Boot BOM과 호환되게 정리한다.
- [ ] 개발/테스트/운영 프로필을 분리한다.
- [ ] DB 접속 정보는 환경 변수로 관리한다.
- [ ] 공통 응답, 예외 코드, 로그 형식을 정의한다.
- [ ] 패키지를 `auth`, `user`, `room`, `game`, `chat`, `common` 기준으로 정리한다.
- [ ] `.gitignore`에 IDE, Gradle 캐시, 환경 변수 파일을 반영한다.

- [ ] 생성일, 수정일을 자동 기록한다.
- [ ] 회원 상태(활성/탈퇴/차단)가 필요하면 enum으로 정의한다.

- [ ] 참가자별 직업, 생존 여부, 승리 여부를 저장한다.
- [ ] 게임 종료 기록을 하나의 트랜잭션으로 저장한다.

### 인메모리 게임 상태

- [ ] `PlayerSession`을 정의한다.
- [ ] `GamePhase` enum을 정의한다.
- [ ] `Role` enum을 정의한다.
- [ ] `PlayerStatus` enum을 정의한다.
- [ ] `NightAction`을 정의한다.
- [ ] `roomStates: ConcurrentHashMap<Long, RoomState>`를 구성한다.
- [ ] 방 상태 안에서 참가자, 투표, 밤 행동 데이터의 소유 관계를 명확히 한다.
- [ ] 방 단위 Lock 또는 동기화 전략을 정한다.
- [ ] 게임 종료 및 빈 방 제거 시 메모리를 정리한다.

### 방 목록

- [ ] 방 목록 조회 API를 만든다.
- [ ] 대기 중/게임 중/정원 초과 상태를 구분한다.
- [ ] 방 제목 검색을 연결한다.

- [ ] 비밀번호 방을 자물쇠 아이콘으로 표시한다.
- [ ] 종료되거나 삭제된 방 접근 시 안내 화면을 표시한다.

### 방 생성 및 입장

- [ ] 방 생성 모달 또는 화면을 만든다.
- [ ] 방 제목, 최대 인원, 비밀번호, 공개 여부를 입력받는다.
- [ ] 방 생성자는 자동으로 방장이 된다.
- [ ] 초대 코드 또는 초대 URL을 발급한다.
- [ ] 초대 링크 복사 기능을 구현한다.
- [ ] 비밀번호 검증 후 방에 입장시킨다.
- [ ] 정원 초과 입장을 서버에서 차단한다.
- [ ] 이미 참가 중인 사용자의 중복 입장을 방지한다.
- [ ] 게임 중인 방은 참가와 관전을 구분한다.

### 대기실

- [ ] 참가자 입장/퇴장 이벤트를 전체에 전송한다.
- [ ] 참가자의 준비 상태를 변경한다.
- [ ] 방장은 준비 상태와 별개로 시작 권한을 갖도록 할지 결정한다.
- [ ] 방장만 참가자를 강퇴할 수 있도록 검증한다.
- [ ] 강퇴된 사용자의 즉시 재입장 정책을 정한다.
- [ ] 방장 위임 기능을 구현한다.
- [ ] 시작 최소 인원을 서버에서 검증한다.
- [ ] 전원 준비 여부를 서버에서 계산한다.
- [ ] 게임 시작 이후 신규 참가를 차단한다.

## 5. WebSocket/STOMP 통신

- [ ] WebSocket 엔드포인트와 STOMP broker를 설정한다.
- [ ] SockJS 사용 여부를 결정한다.
- [ ] 연결 시 인증 사용자를 WebSocket 세션과 연결한다.
- [ ] 구독 시 해당 방 참가자인지 검증한다.
- [ ] 클라이언트가 다른 사용자의 ID로 메시지를 보내지 못하게 한다.
- [ ] `/app/room/{roomId}/chat` 송신을 구현한다.
- [ ] `/app/room/{roomId}/mafia-chat` 송신을 구현한다.
- [ ] `/app/room/{roomId}/vote` 송신을 구현한다.
- [ ] `/sub/room/{roomId}/public` 구독을 구현한다.
- [ ] `/sub/room/{roomId}/mafia` 구독 권한을 마피아로 제한한다.
- [ ] `/user/sub/room/{roomId}/private` 개인 알림을 구현한다.
- [ ] 메시지 타입을 `JOIN`, `LEAVE`, `CHAT`, `PHASE`, `VOTE`, `RESULT`, `ERROR` 등으로 정의한다.
- [ ] 메시지 DTO에 서버 시각과 이벤트 ID를 포함한다.
- [ ] 연결 종료 이벤트와 비정상 종료를 처리한다.
- [ ] 재접속 후 현재 방 상태 전체를 다시 받을 수 있게 한다.

## 6. 게임 상태 머신

- [ ] 상태 전이를 한 서비스에서만 수행하도록 설계한다.
- [ ] `WAITING -> ROLE_ASSIGNMENT` 전이를 구현한다.
- [ ] `ROLE_ASSIGNMENT -> DAY_DISCUSSION` 전이를 구현한다.
- [ ] `DAY_DISCUSSION -> NOMINATION_VOTE` 전이를 구현한다.
- [ ] `NOMINATION_VOTE -> FINAL_DEFENSE` 전이를 구현한다.
- [ ] `FINAL_DEFENSE -> EXECUTION_VOTE` 전이를 구현한다.
- [ ] `EXECUTION_VOTE -> NIGHT` 전이를 구현한다.
- [ ] `NIGHT -> RESULT -> DAY_DISCUSSION` 반복을 구현한다.
- [ ] 게임 종료 상태를 구현한다.
- [ ] 잘못된 페이즈의 행동을 서버에서 거부한다.
- [ ] 페이즈 시작 시 필요한 임시 데이터만 초기화한다.
- [ ] 하루 수(`dayCount`)를 정확히 증가시킨다.
- [ ] 상태 전이 이벤트를 전체 참가자에게 전송한다.

## 7. 서버 타이머

- [ ] 페이즈별 제한 시간을 설정 파일로 분리한다.
- [ ] 서버 기준 종료 시각을 게임 상태에 저장한다.
- [ ] 1초마다 남은 시간을 브로드캐스트한다.
- [ ] 타이머가 0이 되면 페이즈를 한 번만 전환한다.
- [ ] 서버 지연이 발생해도 종료 시각 기준으로 남은 시간을 계산한다.
- [ ] 여러 방의 타이머가 서로 영향을 주지 않게 한다.
- [ ] 게임 종료 또는 방 삭제 시 예약 작업을 취소한다.
- [ ] 클라이언트는 서버가 보낸 시각을 기준으로 화면만 보간한다.

## 8. 직업 배정 및 밤 행동

- [ ] 인원별 마피아 수를 확정한다.
- [ ] 의사 1명, 경찰 1명, 나머지 시민 배정 규칙을 구현한다.
- [ ] 직업을 안전한 난수 방식으로 섞어 배정한다.
- [ ] 각 사용자에게 자신의 직업만 개인 메시지로 전송한다.
- [ ] 마피아끼리 서로를 확인할 수 있게 한다.
- [ ] 살아 있는 사용자만 밤 행동을 할 수 있게 한다.
- [ ] 마피아가 처치 대상을 선택할 수 있게 한다.
- [ ] 여러 마피아의 대상 합의 규칙을 구현한다.
- [ ] 의사가 한 명을 보호할 수 있게 한다.
- [ ] 경찰이 한 명을 조사할 수 있게 한다.
- [ ] 경찰 조사 결과를 경찰에게만 전송한다.
- [ ] 같은 밤에 행동을 다시 제출하면 기존 선택을 교체할지 결정한다.
- [ ] 밤 종료 시 마피아 대상과 의사 대상을 원자적으로 계산한다.
- [ ] 처치 대상과 보호 대상이 같으면 사망자를 만들지 않는다.
- [ ] 사망 처리 후 승리 조건을 검사한다.

## 9. 채팅 및 투표

### 채팅

- [ ] 낮에는 생존자 전체 채팅을 허용한다.
- [ ] 밤에는 마피아 전용 채팅만 허용한다.
- [ ] 사망자는 관전자 채팅만 사용할 수 있게 한다.
- [ ] 채팅 권한을 클라이언트가 아닌 서버에서 검증한다.
- [ ] 메시지 길이 제한과 빈 메시지 검증을 적용한다.
- [ ] HTML 태그를 이스케이프해 XSS를 방지한다.
- [ ] 도배 방지를 위한 간단한 전송 제한을 적용한다.

### 투표

- [ ] 생존자만 투표할 수 있게 한다.
- [ ] 자기 자신 투표 허용 여부를 정한다.
- [ ] 페이즈별 1인 1표를 보장한다.
- [ ] 재투표 시 기존 표를 교체할지 차단할지 정한다.
- [ ] 동시 투표 집계를 방 단위 Lock으로 보호한다.
- [ ] 지목 투표의 최다 득표자를 계산한다.
- [ ] 동률 결과 처리 규칙을 적용한다.
- [ ] 최후 변론 대상만 발언 가능하게 할지 결정한다.
- [ ] 찬반 투표 결과에 따라 처형 여부를 결정한다.
- [ ] 처형 이후 승리 조건을 검사한다.

## 10. 승패 판정 및 게임 종료

- [ ] 살아 있는 마피아 수와 시민 진영 수를 계산한다.
- [ ] 마피아 수가 시민 진영 수 이상이면 마피아 승리로 처리한다.
- [ ] 마피아가 0명이면 시민 승리로 처리한다.
- [ ] 승패 판정이 중복 실행되지 않게 한다.
- [ ] 게임 종료 시 모든 사용자의 직업을 공개한다.
- [ ] 전적과 게임 기록을 DB에 저장한다.
- [ ] 결과 화면에 승리 팀, 역할, 생존 여부를 표시한다.
- [ ] 다시 하기와 로비 이동 기능을 제공한다.
- [ ] 게임 종료 후 일정 시간이 지나면 인메모리 상태를 제거한다.

## 12. 예외 및 보안

- [ ] 존재하지 않는 방 접근을 404로 처리한다.
- [ ] 잘못된 비밀번호와 정원 초과를 명확한 오류로 응답한다.
- [ ] 권한 없는 강퇴, 시작, 직업 행동 요청을 거부한다.
- [ ] 다른 방의 채널 구독과 메시지 전송을 차단한다.
- [ ] URL의 사용자 ID나 역할 값을 신뢰하지 않는다.
- [ ] 게임의 실제 직업 정보가 전체 응답에 포함되지 않게 한다.
- [ ] REST와 WebSocket 입력 DTO에 Bean Validation을 적용한다.
- [ ] 전역 예외 처리기를 구현한다.
- [ ] 사용자가 볼 오류와 서버 로그용 오류를 분리한다.
- [ ] 운영 환경에서 상세 스택 트레이스를 노출하지 않는다.
- [ ] SQL Injection, XSS, CSRF 기본 점검을 수행한다.

## 14. 배포 준비

- [ ] 운영 DB 스키마 생성 방식을 정한다. 가능하면 Flyway를 사용한다.
- [ ] 서버 타임존을 명시한다.
- [ ] HTTPS와 Secure Cookie를 적용한다.
- [ ] WebSocket 프록시 설정을 확인한다.
- [ ] 환경 변수와 비밀 정보를 배포 환경에 등록한다.
- [ ] 애플리케이션 상태 확인 엔드포인트를 추가한다.
- [ ] 주요 이벤트와 오류 로그를 남긴다.
- [ ] 동시 접속 목표 인원으로 부하 테스트를 수행한다.
- [ ] 인메모리 상태를 사용하므로 서버 재시작 시 게임이 사라짐을 운영 정책에 명시한다.
- [ ] 다중 서버 확장은 MVP 이후 Redis Pub/Sub 및 분산 상태 저장으로 분리한다.

## MVP 완료 조건(Definition of Done)

- [ ] 로그인한 4~8명이 같은 방에 입장할 수 있다.
- [ ] 준비 완료 후 한 번만 게임이 시작된다.
- [ ] 각 참가자가 자신의 직업만 확인할 수 있다.
- [ ] 낮, 지목 투표, 변론, 찬반 투표, 밤 페이즈가 서버 시간으로 진행된다.
- [ ] 마피아, 의사, 경찰의 밤 행동이 정상 반영된다.
- [ ] 채팅 채널이 역할과 생존 상태에 따라 분리된다.
- [ ] 모든 투표가 1인 1표로 안전하게 집계된다.
- [ ] 시민 또는 마피아 승리 조건이 정확히 판정된다.
- [ ] 게임 결과와 개인 전적이 DB에 저장된다.
- [ ] 새로고침 또는 짧은 연결 끊김 이후 게임 상태를 복원할 수 있다.
- [ ] 최소 한 판을 여러 브라우저에서 끝까지 완주한다.
