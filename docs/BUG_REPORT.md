# MAFIAGAME 버그 리포트

> develop 브랜치 기준 버그 정리 및 수정 예정사항

## 1. 게임 종료 시 채널이 사망자 채널로 고정되는 문제

### 현상

- 게임이 종료되는 시점에 채팅 채널을 사용하거나 채널 상태가 갱신되면 사용자의 채널 선택이 비정상적으로 변경된다.
- 게임 종료 후 생존 여부와 관계없이 사망자 채널만 사용할 수 있는 상태로 노출되는 문제가 있다.
- 게임 종료 화면에서 일반 채널 또는 역할에 맞는 채널 상태로 복귀하지 못한다.

### 재현 시나리오

1. 게임방에 입장해 게임을 시작한다.
2. 마지막 처형 또는 밤 결과 처리로 게임이 종료되는 상황을 만든다.
3. 게임 종료 이벤트와 채널 상태 갱신이 동시에 발생하는 시점에 채팅을 사용하거나 채널 선택기를 확인한다.
4. 게임 종료 후 채널 선택기가 사망자 채널만 사용할 수 있는 상태인지 확인한다.

### 기대 동작

- 게임 종료 후에도 플레이어의 생존 여부와 권한에 맞는 채널만 표시·활성화되어야 한다.
- 생존자는 공개 채널을 사용할 수 있어야 한다.
- 사망자 채널은 사망자와 영매사 등 허용된 사용자에게만 표시·활성화되어야 한다.
- 게임 종료에 따른 결과 화면 전환이 채널 권한 상태를 잘못 덮어쓰지 않아야 한다.

### 수정 예정

- 게임 종료 이벤트 처리와 채널 상태 초기화 순서를 점검한다.
- `FINISHED` 상태에서 생존 여부·역할·채널 권한을 다시 계산하도록 수정한다.
- 게임 종료 시 채널 선택기와 채팅 입력 상태가 사용자 권한에 맞게 갱신되는지 테스트 코드를 추가한다.
- 생존자·사망자·영매사별 게임 종료 채널 상태를 QA 시나리오에 추가한다.

## 2. 경찰 조사 결과에 진영을 표시하는 문제

### 현상

- 경찰이 밤에 플레이어를 조사하면 조사 결과 상단에 개별 역할 또는 `마피아`와 같은 역할명이 먼저 표시된다.
- 경찰이 전략을 판단할 때 필요한 진영 정보가 결과 제목·상단 영역에서 명확하게 구분되지 않는다.

### 기대 동작

- 경찰 조사 결과 상단에 조사 대상의 진영을 표시한다.
- 마피아 또는 스파이처럼 마피아팀에 속한 대상은 `마피아팀`으로 표시한다.
- 경찰·의사·군인·영매사·시민처럼 시민 진영에 속한 대상은 `시민팀`으로 표시한다.
- 기존 조사 결과의 상세 역할 정보가 필요한 경우에도 진영 표시를 우선하고, 역할명은 상세 정보 영역에서 구분한다.

### 수정 예정

- 경찰 조사 결과 DTO와 화면 표시 데이터를 진영 기준으로 정비한다.
- 조사 결과 상단 라벨을 `마피아팀` 또는 `시민팀`으로 출력하도록 변경한다.
- 스파이를 포함한 마피아팀과 시민팀의 역할별 조사 결과 테스트를 추가한다.
- 경찰 화면의 결과 제목·상단 진영 라벨·상세 역할 정보가 서로 일치하는지 QA 시나리오로 검증한다.

## 3. 서비스 실행 중 SCP 전송으로 파일이 손상되어 `ThrowableProxy` 오류가 반복되는 문제

### 현상

- 서비스가 실행 중인 상태에서 SCP로 파일을 전송한 뒤 파일이 손상되었다.
- 이후 `NoClassDefFoundError: ...ThrowableProxy` 오류가 발생하고 로그에 반복해서 출력된다.
- 손상된 파일의 정확한 경로와 전송 중 서비스 동작이 오류를 유발한 구체적인 과정은 추가 확인이 필요하다.

### 재현 시나리오

1. 서비스를 실행한 상태에서 SCP로 서비스 파일을 덮어쓰거나 교체한다.
2. 서비스 로그에서 `NoClassDefFoundError: ...ThrowableProxy`가 반복되는지 확인한다.
3. 전송 전후의 파일 크기와 체크섬, SCP 종료 상태를 비교해 손상 여부를 확인한다.

### 기대 동작

- 실행 중인 서비스 파일은 배포 전송으로 부분 기록되거나 손상되지 않아야 한다.
- 배포 파일은 전송과 무결성 확인이 끝난 뒤 서비스에 반영되어야 하며, 오류 발생 시 손상되지 않은 이전 파일로 복구할 수 있어야 한다.

### 원인 및 후속 조치

- 보고된 원인은 서비스 실행 중 SCP 전송으로 인한 파일 손상이다.
- 어떤 파일이 손상되었는지와 `ThrowableProxy` 로딩 오류로 이어진 세부 경로는 아직 확인되지 않았다.
- 서비스를 종료한 뒤 손상된 파일을 삭제하고 SCP로 다시 업로드한 다음 서비스를 실행해 문제가 해결되었다.
- 재발 방지를 위해 배포 파일은 서비스 종료 후 교체하고, 업로드가 끝난 뒤 서비스를 다시 실행한다.
- 손상된 파일의 정확한 경로와 `ThrowableProxy` 오류가 반복된 세부 원인은 미확인이다.
